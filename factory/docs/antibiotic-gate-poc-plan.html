Antibiotic Gate: a measurable ADK decision-tree agent

A trigger wakes the agent, it walks a versioned clinical decision tree over one antibiotic order, and it pushes a determination with its full reasoning path to a review UI where a pharmacist approves or denies. Every one of those human decisions is a label, so accuracy is measured on every run — not once at demo time.

01

The one design rule

The tree decides; Gemini only explains. Traversal is deterministic Python over a tree.yaml a clinician can read and diff. The LLM receives an already-decided determination and writes the reviewer-facing rationale. That split is what makes this POC measurable at all: the decision is reproducible bit-for-bit, so a change in accuracy is always attributable to a tree version, a data change, or a prompt version — never to sampling noise.

It also matches the chassis we already have. rules.py proved the deterministic-core pattern for reconciliation; a decision tree is the same socket with an ordered graph and a trace instead of a flat rule list.

The decision tree and its business rules

Eleven decision nodes, four outcome types, one reason code per leaf. Ordering is deliberate: documentation and sepsis are checked before anything drug-specific, absolute contraindications before dose refinements. Flags do not terminate — they accumulate on the trace and force the T80 roll-up to escalate.

04

Datasets

All synthetic, generated by one seeded script so the fixture is reproducible. Small on purpose: 400 patients and 500 orders exercise every branch without making the eval slow. Roughly a dozen rows are deliberately hard — a mild-rash penicillin history where a cephalosporin is reasonable, eGFR at 29 and 31, a culture reported R with the drug ordered anyway, nitrofurantoin at 38 weeks.

Statistical honesty: at n=150 the 95% interval on decision accuracy is about ±3.5 points, so treat sub-2-point moves as noise and read the trend, not the tick. The golden labels are the ceiling on what we can measure — a second labeler on a 30-case overlap gives us an inter-rater number to quote alongside every accuracy figure.

06

What the dev makes tunable

Nothing clinical or behavioural is allowed to live in Python. Three declarative surfaces, each versioned in git and each stamped onto every result row so any accuracy number can be traced back to the exact configuration that produced it.

# agents/antibiotic_gate/config.yaml
name: antibiotic_gate
model: gemini-2.5-flash
surface: background
autonomy: L2                              # nothing is dispensed without a human
trigger: { kind: schedule, schedule: "*/15 * * * *" }
sources: [patients, allergies, medications, labs, vitals, orders, formulary]
tree:    agents/antibiotic_gate/tree.yaml    # NEW — the decision tree as data
prompts: prompts/antibiotic_gate/            # NEW — versioned templates
action:
  write_bigquery: dq_results.antibiotic_determinations
  hitl_review: true
  hitl_min_severity: ALL                     # POC: every order gets a reviewer
eval:
  golden: eval/golden_cases.jsonl
  gates: { safety_recall: 1.0, decision_accuracy: 0.95, regression_tolerance: 0.02 }
business_context:
  escalate_classes: [carbapenem, glycopeptide, oxazolidinone]
  sepsis_criteria_min: 2

New in the hub

  • decision_tree.py — load tree.yaml, traverse(facts) returns decision, reason code, node path, citations. Pure, no I/O, no LLM.
  • patient_facts.py — assemble one facts object per order from the seven sources.
  • prompts.py — versioned template loader; prompt_version travels with every row.
  • eval/ — golden.py, metrics.py, gates.py, runner.py.
  • observability.py — add a run id, one structured log line per node visited, and the ops.agent_runs writer.
  • ui/app.py — clinical review card and a /scorecard route.

Deliberately untouched

  • sources.py — the connector interface already abstracts CSV-offline from BigQuery-online. New tables are registry entries.
  • guardrails.py — tool allow-list, cost cap and de-identification apply as-is.
  • sinks.py, settings.py, runtime.py deploy path, the Terraform module pattern.

If a second spoke needs no hub changes beyond a config and a tree, the chassis claim is proven. That is a POC finding worth reporting on its own.

Two review gates. End of day 4: a clinical reviewer reads tree.yaml line by line against the rules table above, before any eval work is built on top of it. End of day 9: we accept the metric definitions and the baseline. Everything else is the dev's call.

Stretch, only if days 1–9 land clean. Run the same golden set through an LLM-only variant — tools and a prompt, no tree — and report both accuracy numbers side by side. One table that quantifies why the deterministic core is the right architecture is worth more to the steering committee than any amount of assertion.

08

Scope boundary and risks

Explicitly out of scope

  • This is not clinical software and is not a clinical decision support claim. Synthetic data, no PHI, no real formulary, no dispensing integration.
  • AUTO_APPROVE_ENABLED=0 for the entire POC. The autonomy ladder stops at L2; the config field exists so the conversation about L3 is a config review, not a rewrite.
  • No real EHR or ordering-system connector. The order table is the seam.

Risks we are managing

  • Label ceiling. One labeler on 150 cases bounds what we can claim; mitigated by the 30-case inter-rater overlap.
  • Tree drift. Guidelines change. tree_version on every row means an accuracy shift is always attributable rather than mysterious.
  • LLM availability. Gemini is on the explanation path only; the existing template fallback means a model outage degrades wording, not determinations.
  • Over-blocking. A tree tuned only for safety recall escalates everything. The false-deny rate is tracked precisely so we notice.
Plan for a proof of concept on the existing agent_factory chassis. Synthetic data throughout; not a clinical decision support system and not for patient care.
